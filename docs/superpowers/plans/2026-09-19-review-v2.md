# Review v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Claude reviewer (Sonnet 5) decides; clean PRs auto-merge; everything else reaches the maintainer on Telegram with Fix / Approve & merge / Deny buttons.

**Architecture:** Two PRs. PR A adds a stdlib-Python Lambda behind a Function URL that turns a Telegram button tap into a `workflow_dispatch` of `telegram-action.yml` (plus the CI-role permissions it needs). PR B rewrites the gate: `guard.yml` keeps its job name, reads a `PASS|FAIL` verdict + a mechanical hard floor, arms auto-merge or sends a Telegram message with buttons; `telegram-action.yml` executes approve/deny/fix with a GitHub App token.

**Tech Stack:** bash (gate scripts, plain-bash tests in `tests/guard/`), Python 3.12 stdlib + boto3 from the Lambda runtime, Terraform 1.14.9 (aws provider, hashicorp/archive), GitHub Actions, anthropics/claude-code-action, actions/create-github-app-token.

**Spec:** `docs/superpowers/specs/2026-09-19-review-v2-design.md`

## Global Constraints

- Conventional commits, **no attribution trailers** (maintainer rule).
- Every action pinned to a full commit SHA with `# vX.Y.Z`; each job declares minimum `permissions`; no `${{ }}` inside `run:` (pass through `env:`).
- AWS names `ned-*`; IAM least privilege, resource-scoped; boundaries on every created principal (`ned-role-boundary` for roles).
- Secrets never in git or Terraform state. SSM names: `/ned/telegram/bot-token`, `/ned/telegram/webhook-secret`, `/ned/github/dispatch-token` (SecureString), `/ned/telegram/approver-id` (String). GitHub: secret `NED_APP_PRIVATE_KEY` and variable `NED_APP_ID` live in environment `ned-bot` (deployment branches: `main` only, so no other branch's workflow can mint an app token); `NED_APP_SLUG` is a repo variable (not secret — the guard needs it too).
- Review model id: `claude-sonnet-5`. Verdict contract lines: `VERDICT: PASS|FAIL`, `WHY: …`, `FIX: …|none`.
- `callback_data` format: `^([adf]):([1-9][0-9]{0,6}):([0-9a-f]{40})$` (a=approve, d=deny, f=fix).
- Required check names stay `lint`, `check`, `guard`, `module-tests (…)`.
- Max 2 fix rounds per PR. At most one Telegram message per head SHA.
- Terraform tests: `mock_provider "aws" {}` + `command = apply`; IAM statements as locals so tests assert on them.
- Agents never merge, apply, set secrets/variables, or add labels. Human steps are marked **[HUMAN]**.

## Deviations from the spec (decided while planning)

- **No reserved concurrency** on the Lambda: new accounts have a total concurrency limit of 10 and AWS refuses reservations that leave < 10 unreserved. The account limit already caps abuse; forged requests are rejected on the secret header before any work.
- **No terraform-aws-modules/lambda:** its packaging runs a `data "external"` program at plan time, which our own review rules flag. Plain `aws_lambda_function` + `archive_file` instead (~60 lines).
- **Apply needs the zip:** a saved plan does not re-read `archive_file`, and the apply job runs on a fresh runner. The plan job stashes a tarball of `tfplan` + `.build/` and the sha256 covers the tarball.
- Floor also covers `apps/telegram-approver/**` (the Lambda code is part of the review system).

```python
"""Telegram button tap -> workflow_dispatch of telegram-action.yml. Stdlib + boto3 (Lambda runtime) only."""
import base64
import hmac
import json
import os
import re
import urllib.request

CALLBACK = re.compile(r"^([adf]):([1-9][0-9]{0,6}):([0-9a-f]{40})$")
ACTIONS = {"a": "approve", "d": "deny", "f": "fix"}
_cfg = None


def handle(event, cfg, dispatch, answer):
    headers = {k.lower(): v for k, v in (event.get("headers") or {}).items()}
    got = headers.get("x-telegram-bot-api-secret-token", "")
    if not hmac.compare_digest(got.encode(), cfg["webhook_secret"].encode()):
        return 401
    body = event.get("body") or "{}"
    if event.get("isBase64Encoded"):
        body = base64.b64decode(body).decode()
    query = json.loads(body).get("callback_query")
    if not query:
        return 200
    cid = query["id"]
    if str(query.get("from", {}).get("id")) != cfg["approver_id"]:
        answer(cid, "not authorised")
        return 200
    m = CALLBACK.match(query.get("data") or "")
    if not m:
        answer(cid, "invalid button")
        return 200
    action, pr, sha = ACTIONS[m[1]], m[2], m[3]
    if dispatch(action, pr, sha):
        answer(cid, f"⏳ {action} requested for PR #{pr}")
    else:
        answer(cid, "failed, try again")
    return 200


def _post(url, payload, headers):
    req = urllib.request.Request(url, json.dumps(payload).encode(), {"Content-Type": "application/json", **headers})
    with urllib.request.urlopen(req, timeout=10) as resp:
        return resp.status


def _config():
    global _cfg
    if _cfg is None:
        import boto3

        names = {k: os.environ[f"{k.upper()}_PARAM"] for k in ("bot_token", "webhook_secret", "dispatch_token", "approver_id")}
        resp = boto3.client("ssm").get_parameters(Names=list(names.values()), WithDecryption=True)
        values = {p["Name"]: p["Value"] for p in resp["Parameters"]}
        _cfg = {k: values[v] for k, v in names.items()}
    return _cfg


def lambda_handler(event, context):
    cfg = _config()

    def dispatch(action, pr, sha):
        url = f"https://api.github.com/repos/{os.environ['REPO']}/actions/workflows/telegram-action.yml/dispatches"
        try:
            return _post(url, {"ref": "main", "inputs": {"action": action, "pr": pr, "sha": sha}}, {
                "Authorization": f"Bearer {cfg['dispatch_token']}",
                "Accept": "application/vnd.github+json",
                "X-GitHub-Api-Version": "2022-11-28",
                "User-Agent": "ned-telegram-approver",
            }) == 204
        except OSError as err:  # urllib.error.URLError/HTTPError subclass OSError
            print(f"dispatch failed: {err}")
            return False

    def answer(cid, text):
        try:
            _post(f"https://api.telegram.org/bot{cfg['bot_token']}/answerCallbackQuery", {"callback_query_id": cid, "text": text}, {})
        except OSError as err:
            print(f"answerCallbackQuery failed: {type(err).__name__}")  # never log the URL: it contains the bot token

    return {"statusCode": handle(event, cfg, dispatch, answer), "body": ""}
```

```bash
#!/usr/bin/env bash
# Hard floor: what always needs the maintainer, whatever the review says. stdin: "<STATUS>\t<path>[\t<new>]".
# Env: PLAN_FILE PR_ACTOR PR_TITLE. Prints floor=<reasons|none>, pending=, destroys=.
set -euo pipefail
reasons=(); pending=false; destroys=0; touches_infra=false
dependabot=false; [ "${PR_ACTOR:-}" = "dependabot[bot]" ] && dependabot=true

check_path() {
  case "$1" in
    .github/dependabot.yml) ;;
    .github/*|CLAUDE.md|.claude/*|infra/modules/telegram-approver/*|apps/telegram-approver/*)
      # Dependabot only bumps pinned versions; its author field is server-set.
      [ "$dependabot" = true ] || reasons+=("review system changed ($1)") ;;
  esac
  case "$1" in infra/*) touches_infra=true;; esac
}

while IFS=$'\t' read -r status path newpath || [ -n "${status:-}" ]; do
  status=${status%$'\r'}; path=${path%$'\r'}; newpath=${newpath%$'\r'}
  [ -z "${path:-}" ] && continue
  check_path "$path"
  [ -n "${newpath:-}" ] && check_path "$newpath"
done

if [ "$touches_infra" = true ]; then
  if [ -z "${PLAN_FILE:-}" ] || [ ! -f "$PLAN_FILE" ]; then
    pending=true
  else
    destroys=$(sed -E -n 's/^Plan: .* ([0-9]+) to destroy(, [0-9]+ to forget)?\.$/\1/p' "$PLAN_FILE" | tail -1)
    destroys=${destroys:-0}
    [ "$destroys" -gt 0 ] && reasons+=("plan destroys ${destroys} resource(s)")
  fi
fi

if [ "$dependabot" = true ]; then
  version_pattern="from ([0-9]+)\.[^ ]* to ([0-9]+)\."
  if [[ "${PR_TITLE:-}" =~ $version_pattern ]] && [ "${BASH_REMATCH[1]}" != "${BASH_REMATCH[2]}" ]; then
    reasons+=("dependabot major bump")
  fi
fi

( IFS=';'; printf 'floor=%s\n' "${reasons[*]:-none}" )
printf 'pending=%s\ndestroys=%s\n' "$pending" "$destroys"
```

### Task 11: `telegram-action.yml` (Opus)

**Files:** Create `.github/workflows/telegram-action.yml`.

**Interfaces:**
- Consumes: dispatch inputs from the Lambda (Task 2 contract), `guard-verdicts.sh` (`fix`), notify action, secrets `NED_APP_PRIVATE_KEY`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `CLAUDE_CODE_OAUTH_TOKEN`, vars `NED_APP_ID` (from the `ned-bot` environment the job runs under), `NED_APP_SLUG` (repo variable).
- Produces: label `human-approved` by the app (approve), closed PR + comment (deny), fix commit pushed by the app + marker comment `<!-- ned-fix:<sha> --> fix round N requested via Telegram` by the app (fix).

- [ ] **Step 1: Look up pins** — latest release commit SHAs for `actions/create-github-app-token` (`gh api repos/actions/create-github-app-token/releases/latest -q .tag_name` then `gh api repos/actions/create-github-app-token/commits/<tag> -q .sha`). Reuse the checkout and claude-code-action pins from `claude-review.yml`.
- [ ] **Step 2: Write the workflow:**

```yaml
name: telegram-action

# Dispatched by the telegram-approver Lambda (Actions:write PAT) or by the maintainer from the UI.
on:
  workflow_dispatch:
    inputs:
      action: { description: "approve | deny | fix", type: choice, options: [approve, deny, fix], required: true }
      pr: { description: "PR number", type: string, required: true }
      sha: { description: "PR head SHA the button was sent for", type: string, required: true }

permissions: {}

concurrency:
  group: telegram-action-${{ inputs.pr }}
  cancel-in-progress: false

jobs:
  act:
    if: github.ref == 'refs/heads/main'
    runs-on: ubuntu-latest
    timeout-minutes: 20
    # NED_APP_PRIVATE_KEY/NED_APP_ID live in this environment (deployment branches: main only), so a
    # workflow triggered from any other ref cannot mint an app token even if it reaches this job.
    environment: ned-bot
    permissions:
      contents: read
    env:
      REPO: ${{ github.repository }}
      ACTION: ${{ inputs.action }}
      PR: ${{ inputs.pr }}
      SHA: ${{ inputs.sha }}
      APP_BOT: ${{ vars.NED_APP_SLUG }}[bot]
    steps:
      - uses: actions/checkout@<pin> # vX
        with:
          persist-credentials: false
      - name: Validate inputs
        run: '[[ "$PR" =~ ^[1-9][0-9]{0,6}$ && "$SHA" =~ ^[0-9a-f]{40}$ ]] || { echo "::error::bad inputs"; exit 1; }'
      - id: app
        uses: actions/create-github-app-token@<pin> # vX
        with:
          app-id: ${{ vars.NED_APP_ID }}
          private-key: ${{ secrets.NED_APP_PRIVATE_KEY }}
      - name: PR still at the tapped head?
        id: state
        env:
          GH_TOKEN: ${{ steps.app.outputs.token }}
        run: |
          gh pr view "$PR" -R "$REPO" --json state,headRefOid,headRefName,isCrossRepository > pr.json
          ok=true; why=
          [ "$(jq -r .state pr.json)" = OPEN ] || { ok=false; why="PR is not open"; }
          [ "$(jq -r .headRefOid pr.json)" = "$SHA" ] || { ok=false; why="PR changed since the message — a new review is coming"; }
          [ "$(jq -r .isCrossRepository pr.json)" = false ] || { ok=false; why="fork PRs are not handled from Telegram"; }
          { echo "ok=$ok"; echo "why=$why"; echo "branch=$(jq -r .headRefName pr.json)"; } >> "$GITHUB_OUTPUT"
      - name: Approve
        if: steps.state.outputs.ok == 'true' && inputs.action == 'approve'
        env:
          GH_TOKEN: ${{ steps.app.outputs.token }}
        run: gh pr edit "$PR" -R "$REPO" --add-label human-approved
      - name: Deny
        if: steps.state.outputs.ok == 'true' && inputs.action == 'deny'
        env:
          GH_TOKEN: ${{ steps.app.outputs.token }}
        run: gh pr close "$PR" -R "$REPO" --comment "denied via Telegram"
      - name: Fix — round limit and fix text
        id: fix
        if: steps.state.outputs.ok == 'true' && inputs.action == 'fix'
        env:
          GH_TOKEN: ${{ steps.app.outputs.token }}
          BRANCH: ${{ steps.state.outputs.branch }}
        run: |
          gh api "repos/$REPO/issues/$PR/comments" --paginate | jq -s add > comments.json
          rounds=$(jq --arg b "$APP_BOT" '[.[] | select(.user.login == $b and ((.body // "") | startswith("<!-- ned-fix:")))] | length' comments.json)
          [ "$rounds" -lt 2 ] || { echo "go=false" >> "$GITHUB_OUTPUT"; echo "why=2 fix rounds used — approve or deny" >> "$GITHUB_OUTPUT"; exit 0; }
          # HEAD_TIME: the verdict must be newer than this head; the guard's first run for it is the reference.
          head_time=$(bash .github/scripts/guard-head-runs.sh "$SHA" | jq -r 'map(.created_at) | min // empty')
          fix=$(COMMENTS_JSON=comments.json HEAD_TIME="${head_time:-1970-01-01T00:00:00Z}" bash .github/scripts/guard-verdicts.sh | sed -n 's/^fix=//p')
          [ -n "$fix" ] || { echo "go=false" >> "$GITHUB_OUTPUT"; echo "why=no fix in the latest review" >> "$GITHUB_OUTPUT"; exit 0; }
          gh pr comment "$PR" -R "$REPO" --body "<!-- ned-fix:$SHA --> fix round $((rounds + 1)) requested via Telegram"
          d=$(openssl rand -hex 8); { echo "go=true"; echo "text<<$d"; echo "$fix"; echo "$d"; } >> "$GITHUB_OUTPUT"
      - name: Check out PR branch
        if: steps.fix.outputs.go == 'true'
        uses: actions/checkout@<pin> # vX
        with:
          ref: ${{ steps.state.outputs.branch }}
          path: pr
          token: ${{ steps.app.outputs.token }}
          persist-credentials: false
      - name: Claude applies the fix (edit tools only, no shell)
        if: steps.fix.outputs.go == 'true'
        uses: anthropics/claude-code-action@<pin> # vX
        with:
          claude_code_oauth_token: ${{ secrets.CLAUDE_CODE_OAUTH_TOKEN }}
          prompt: |
            Working directory: ./pr (a checkout of PR #${{ inputs.pr }}).
            Apply exactly this reviewer fix and nothing else:
            ${{ steps.fix.outputs.text }}
          claude_args: '--allowedTools "Read,Edit,Write,Glob,Grep" --model claude-sonnet-5'
      - name: Commit and push as the Ned app
        id: push
        if: steps.fix.outputs.go == 'true'
        working-directory: pr
        env:
          TOKEN: ${{ steps.app.outputs.token }}
          BRANCH: ${{ steps.state.outputs.branch }}
        run: |
          if git diff --quiet; then echo "pushed=false" >> "$GITHUB_OUTPUT"; exit 0; fi
          git -c user.name="$APP_BOT" -c user.email="$APP_BOT@users.noreply.github.com" commit -am "fix: apply review fix from Telegram"
          git push "https://x-access-token:$TOKEN@github.com/$REPO.git" "HEAD:$BRANCH"
          echo "pushed=true" >> "$GITHUB_OUTPUT"
      - uses: ./.github/actions/telegram-notify
        if: always()
        env:
          TELEGRAM_BOT_TOKEN: ${{ secrets.TELEGRAM_BOT_TOKEN }}
          TELEGRAM_CHAT_ID: ${{ secrets.TELEGRAM_CHAT_ID }}
        with:
          message: "PR #{1} · {2}: {3}"
          arg1: ${{ inputs.pr }}
          arg2: ${{ inputs.action }}
          arg3: ${{ steps.state.outputs.ok != 'true' && steps.state.outputs.why || steps.fix.outputs.why || (steps.push.outputs.pushed == 'false' && 'Claude produced no change') || (job.status == 'success' && 'done' || 'failed — see Actions') }}
```
  Note `guard-head-runs.sh` needs `REPO`, `PR`, `BRANCH` in env and `actions: read` is not required for public repos' run listing with the app token (the app token has no Actions permission; if the call is refused, add `actions: read` to the job's `permissions` and use `GH_TOKEN: ${{ github.token }}` for that one call).
